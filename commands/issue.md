# 任务：方案同步与分支初始化

请你作为技术主管，严格执行以下自动化流程：

### 第一步：整理方案内容
1. **回顾上下文**：提取我们在“计划模式 (Plan Mode)”中刚刚讨论过的详细设计方案、架构改动和待办事项。
2. **生成 Issue 标题**：提炼一个能概括该任务的简洁标题。
3. **编写 Issue 正文**：将设计详情整理为结构清晰的 Markdown 格式，包含背景、技术方案和 Checklists。

### 第二步：推送到 GitHub Issue
1. 调用 `bash` 执行 `gh issue create` 命令。
2. **命令参考**：`gh issue create --title "<标题>" --body "<正文内容>"`
3. **获取编号**：从命令输出中识别生成的 Issue 编号（例如 `#123`）。

### 第三步：创建关联分支
1. **命名规范**：根据 Issue 编号和任务关键词生成分支名。格式建议为：`issue-<编号>-<简短描述>`（例如 `issue-123-auth-logic`）。
2. **切换分支**：调用 `bash` 执行：`git checkout -b <分支名>`

### 第四步：完成反馈
1. 向用户报告 Issue 链接。
2. 告知用户当前已成功切换到新分支，可以开始编写代码。

**要求**：
- 如果本地未安装 `gh` CLI 或未登录，请提示用户先执行 `gh auth login`。
- 整个过程不需要用户手动复制粘贴方案内容，由你自动总结。
