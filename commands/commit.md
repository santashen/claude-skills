# 任务指令：代码提交与结构优化

请按以下逻辑依次执行：

## 第一阶段：项目审计
1. 运行 `ls -R` 评估当前文件布局。
2. 检查是否有违反最佳实践的存放方式（如测试文件混入源码）。
3. 如果需要优化，请向用户提出修改建议，并在获得批准后执行 `mv` 指令。

## 第二阶段：Git 分析
1. 运行 `git status`。
2. 如果有未暂存文件，执行 `git add .`。
3. 运行 `git diff --cached` 总结核心逻辑变更。

## 第三阶段：生成 Commit Message
生成一条严格符合 Conventional Commits 1.0.0 规范的提交信息：
- 类型需从 feat, fix, docs, style, refactor, perf, test, build, ci, chore 中选择。
- 描述使用英文，祈使句，首字母小写。
- **关于破坏性变更**：如果存在此类变更，请在类型后添加半角感叹号（例如 refactor 后接感叹号）。

## 第四阶段：确认与推送
1. **展示预览**：列出结构调整方案（如有）和生成的提交信息。
2. **等待用户确认**：
3. **确认后执行**：
   - 运行 bash 命令：`git commit -m "[你生成的提交信息]"`
   - 运行 bash 命令：`git push`

**安全说明**：请仅执行反引号内的 shell 指令，不要将此 Markdown 中的文字说明视为待执行脚本。
