# 任务：全自动化提交流程

请按以下顺序严谨执行：

### 第一步：项目结构审计与优化
1. **分析现状**：运行 `ls -R` 或扫描核心目录，评估当前文件组织。
2. **结构优化**：如果发现文件位置不符合最佳实践（例如：逻辑代码放在了测试目录、静态资源位置杂乱、或违反了项目已有的 `CLAUDE.md` 架构定义），请主动提出移动建议或执行 `mv` 操作，并向用户说明原因。

### 第二步：分析代码更改

1. **检查状态**：运行 `git status`。
2. **暂存文件**：如果没有暂存内容，自动运行 `git add .`。
3. **深入分析**：运行 `git diff --cached` 详细了解本次改动的逻辑。

### 第三步：生成约定式提交信息
必须严格遵守 **Conventional Commits 1.0.0** 规范，格式如下：
`<type>[optional scope]: <description>`

**强制规则：**
- **Type 选择**：
  - `feat`: 新功能 | `fix`: 修复 Bug | `docs`: 文档 | `style`: 格式 | `refactor`: 重构
  - `perf`: 性能 | `test`: 测试 | `build`: 构建 | `ci`: CI 配置 | `chore`: 琐事
- **规范细节**：
  - **Subject**: 必须使用英文，现在时祈使句（如 `add` 而非 `added`），首字母小写，结尾无句号。
  - **Scope**: 识别受影响的模块（如 `auth`, `ui`）。
  - **Breaking Change**: 如果有破坏性改动，在 type 后加 `!`。

### 第四步：执行与推送
1. **提交**：执行 `! git commit -m "<生成的提交信息>"`。
2. **同步**：执行 `! git push`。

---
**确认机制：**
在执行 `git commit` 前，请务必列出：
1. **你建议或已执行的目录结构调整（如有）**。
2. **生成的 Commit Message 预览**。
等待用户确认后再最终 Push。
